# 머니 커넥션 (Money Connection)

**나스닥100 · 코스피100 · 주요 미국 ETF · 비트코인/이더리움 · 금**이 서로 어떻게 연결돼 움직이는지 —
수익률 상관관계 네트워크와 **포트폴리오·모의 트레이딩**을 매일 자동으로 갱신하는 정적 대시보드입니다.

로고의 점과 선은 이 대시보드가 그리는 상관관계 네트워크 그 자체입니다 — 허브 하나에 세 자산이 연결된 마인드맵 형태입니다.

**사이트**: https://eloyyang.github.io/money-connection/

## 커버리지

| 자산군 | 종목 수 | 출처 |
|---|---|---|
| 나스닥100 | 102 | `api.nasdaq.com` (구성종목·시세·재무제표) |
| 코스피100 | 99 | `finance.naver.com` (구성종목·시세) |
| 미국 ETF | 19 | SPY·QQQ·DIA 등 지수·섹터·채권·원자재 ETF (`data/assets.json`) |
| 암호화폐 | 2 | 비트코인, 이더리움 |
| 금 | 1 | GLD |

총 **223개 자산**이 하나의 상관계수 네트워크에 함께 들어갑니다 — 예를 들어
"코스피가 오르면 나스닥은?", "비트코인은 어떤 종목과 같이 움직이나", "금은 방어 자산 역할을 하고 있나" 같은
질문에 실제 5년치 데이터로 답할 수 있습니다.

## 무엇을 보여주나

| 탭 | 내용 |
|---|---|
| 종목 네트워크 | 자산 간 연결을 **세 가지 기준**으로 봅니다. 종목 선택 시 상관 순위, 주가 차트, 계절성, 종목 성격, 동종 비교, 매크로 민감도, 선행·후행 검증 |
| 트레이딩 | 봉차트 + 보조지표(MA·볼린저·거래량MA·RSI·MACD), 추세선/수평선 그리기, 종목 요약, 즐겨찾기·보유·주도주 목록, 주문 티켓 |
| 포트폴리오 | 모의 트레이딩과 실거래를 한 장부에 기록 — 보유 종목, 평가·실현 손익, 테마/시장/성격별 배분, 거래 내역 (CSV 내보내기) |

좌측 **주도주** 패널은 직전 거래일에 **나스닥100 지수**를 움직인 종목을 등락률과 지수 기여도(등락률 × 시총 비중) 두 기준으로 보여줍니다. 코스피/ETF/암호화폐/금을 섞은 "지수"는 의미가 없어(삼성전자+비트코인+애플을 시총가중 평균하는 것과 같으므로) 이 패널은 나스닥100에만 한정됩니다.

종목을 선택하면 원화(₩)/달러($) 등 **통화가 자동으로 맞춰져** 표시됩니다. 나스닥100 종목에는 **펀더멘털**이 함께 열립니다 — PER(TTM), EPS, 목표주가, 52주 범위, 배당, 연간 매출·영업이익·순이익·총부채·현금(전년 대비 증감), 최근 4분기 실적(컨센서스 대비 서프라이즈)과 향후 분기 추정치. (코스피·ETF·암호화폐·금은 Nasdaq의 재무제표/EPS 엔드포인트가 미국 주식 전용이라 펀더멘털 패널이 뜨지 않습니다.)

**계절성** 차트는 연도별 주가 흐름을 1월~12월 축에 겹쳐 보여줍니다 — 각 해의 1월 1일 종가를 0%로 놓은 누적 수익률이라 "이 종목이 매년 몇 월에 강했는지"를 비교할 수 있습니다. 연도별 모드에는 완료된 연도들의 **평균 경로가 흰 점선**으로 함께 그려져, 올해가 예년 대비 앞서는지 뒤처지는지 바로 비교됩니다(범례에서 끌 수 있음). 범례에서 연도를 켜고 끌 수 있고, **평균** 모드는 평균만 크게 봅니다. 평균은 완료된 연도만 사용합니다(진행 중인 해를 섞으면 연말 구간이 0 쪽으로 끌려 없던 계절성이 생기므로 제외). 1월에 데이터가 시작하지 않는 해는 "1월 대비 누적"이 성립하지 않아 표시하지 않습니다.

**성과** 차트는 매출·순이익 막대(우축 금액)와 순마진 % 라인(좌축)을 겹쳐 보여주며, 연간/분기별로 전환됩니다. 범례로 현금성자산·부채 계열을 추가하거나 계열을 숨길 수 있습니다.

**어닝** 차트는 분기·연간 EPS를 점으로 표시합니다 — 채운 점은 발표된 실적, 빈 점은 컨센서스 추정치. 과거 연간 EPS 실적은 Nasdaq이 제공하지 않아 연간 뷰는 최근 12개월(TTM) 실적에 회계연도별 컨센서스를 잇습니다.

개별 재무 항목을 클릭하면 **연도별 추이 차트**가 펼쳐집니다 — 4년치 막대와 전년 대비 증감률, 누적·연평균 성장률. 실적 섹션을 클릭하면 분기 EPS 차트(실제 막대 + 컨센서스 표시 + 추정 점선)가 열립니다.

봉차트(OHLC)는 축 드래그 확대·이동과 추세선/수평선 그리기를 지원하고, 즐겨찾기는 브라우저에 저장됩니다.

### 연결 기준 (무엇을 "관계"로 볼 것인가)

| 기준 | 선의 의미 | 쓰임 |
|---|---|---|
| 주가 상관 | 선택 기간 일별 수익률의 피어슨 상관계수 | 같이 오르내리는 자산 찾기 |
| 매크로 민감도 | 금리·달러·유가·변동성·신용·시장·금 **7개 팩터 베타 프로필의 유사도** | "같은 매크로 충격에 같이 맞는" 숨은 집중 위험 찾기 |
| 펀더멘털 | PER·매출성장률·순이익률·부채비율 프로필 유사도 | 밸류에이션·성장성이 닮은 종목 묶기 |

매크로 베타는 **거래 가능한 프록시에 대한 최근 1년 일별 회귀**입니다 — 금리는 IEF(미 국채 7-10년) 수익률의 반대 부호, 달러 UUP, 유가 USO, 변동성 VIXY, 신용 HYG, 시장 SPY, 금 GLD. (FRED는 CI 환경에서 접근이 막혀 실제 금리 대신 국채 ETF를 씁니다.) 각 베타는 **t값이 2 미만이면 흐리게** 표시해, 노이즈와 구분되지 않는 값을 실제 노출로 읽지 않도록 했습니다.

월별 **BLS 지표**(소비자물가·실업률·비농업고용)와의 상관도 함께 보여줍니다. 지표 발표는 전월치를 담으므로 **한 달 뒤 수익률과 정렬**했고, 표본이 60개월 남짓이라 노이즈 한계(±2/√n) 안쪽 값은 흐리게 처리합니다.

좌측 범례에서 **테마 / 시장** 을 전환하면 같은 그래프를 두 가지 기준으로 색칠해 볼 수 있습니다 — 8개 업종 테마 기준, 또는 나스닥100·코스피100·미국ETF·암호화폐·금이라는 시장(자산군) 기준. **노드 위치는 어느 쪽에서도 바뀌지 않습니다**(위치는 항상 상관계수가 결정). 강조/숨김 필터 상태는 모드별로 따로 기억됩니다.

**검색**은 티커·회사명이 입력한 글자를 포함하는 종목을 드롭다운 목록으로 보여줍니다(최대 8개, 그 이상은 "외 N개 더 있음"). 방향키로 이동, Enter로 선택, Esc나 바깥 클릭으로 닫힙니다.

## 자동 갱신

`.github/workflows/update.yml`이 **평일 22:00 UTC(한국시간 다음날 07:00)** 에 실행되어

1. **나스닥100**: `api.nasdaq.com/api/quote/list-type/nasdaq100`에서 그날의 구성종목을 가져오고, 처음 보는 종목은 `summary` 엔드포인트의 Sector/Industry로 테마를 자동 분류합니다 (`data/sectors.json`에 캐시).
2. **코스피100**: `finance.naver.com`의 구성종목 페이지(약 10페이지)를 파싱해 종목·시세·시가총액을 가져옵니다. 원화 시가총액은 실시간 환율(`exchangerate-api.com`, 실패 시 1,350원 고정값)로 달러 환산해 노드 크기를 다른 자산과 비교 가능하게 맞춥니다. **테마는 나스닥100과 동일한 8개 업종**으로 분류됩니다 — 코스피100은 별도 버킷이 아니라, 각 종목의 네이버 WICS 업종명(`업종명 : <a>...</a>`)을 나스닥 테마에 매핑해(`data/themes.json`의 `kospi_industry_map`) 삼성전자·SK하이닉스는 AI반도체, LG에너지솔루션은 EV, NAVER는 빅테크 테마에 나스닥 종목들과 함께 묶입니다. 업종 매핑은 `data/kospi_industries.json`에 캐시되어 새 종목만 다시 조회합니다.
3. **ETF/암호화폐/금**: `data/assets.json`에 정의된 고정 목록을 같은 Nasdaq API(`assetclass=etf`/`crypto`)로 가져옵니다. ETF/금은 AUM을 제공하지 않아 최근 60거래일 거래대금 중앙값으로 노드 크기를 근사하고, 암호화폐는 유통량 × 현재가로 실제 시가총액을 계산합니다.
4. 종목마다 5년 일별 OHLCV를 받고, 나스닥100 재무제표·EPS는 하루 25종목씩 순환 갱신하며 (`data/fundamentals.json`)
5. 상관계수·선행후행·로테이션 지표를 **223개 자산 전체**에 대해 다시 계산한 뒤
6. `dist/index.html`을 빌드해 GitHub Pages로 배포합니다.

편입·편출이 생기면 다음 실행에서 자동으로 반영됩니다. 손으로 종목 목록을 고칠 필요가 없습니다.

## 데이터 무결성 장치

- **시세/구성종목 교차검증**: 과거 시세의 마지막 종가가 당일 호가와 25% 이상 어긋나면 다른 종목이 반환된 것으로 보고 Yahoo 데이터로 대체하거나 제외합니다. (Nasdaq API가 특정 심볼을 엉뚱한 종목으로 해석한 사례가 있었습니다)
- **윈저화**: 일간 수익률을 ±25%로 자른 뒤 상관계수를 계산합니다. 분할·분사 같은 1회성 이벤트가 상관계수를 지배하지 못하게 합니다.
- **날짜 기준 1년 창**: 상관계수 네트워크의 "1년"은 거래일 개수(252일)가 아니라 **달력 기준 365일**로 자릅니다. 암호화폐가 주말에도 거래되면서 공유 날짜축이 늘어나, 행 개수 기준으로 잘랐다면 "1년"이 실제로는 8~9개월로 줄어드는 문제가 있었습니다.
- **주도주 지수는 나스닥100 전용**: 서로 다른 자산군을 하나의 "지수"로 시총가중 평균하는 것은 의미가 없으므로, 등락률/지수 기여도 계산은 나스닥100 종목으로만 한정합니다.
- **부분 실패 시 중단**: 종목의 80% 미만만 수집되면 빌드를 실패시켜, 얇은 데이터가 배포되지 않도록 합니다. 이 경우 사이트는 직전 버전을 계속 서비스합니다.

## 한계

과거 데이터의 통계적 성질을 보여줄 뿐이며 투자 자문이 아닙니다. 상관관계는 인과관계가 아니고, 테마 전이 행렬의 표본은 60개월 남짓이라 개별 칸의 확률은 신뢰하기 어렵습니다. 원화·달러 등 서로 다른 통화로 표시된 자산 간 상관계수는 환율 변동분이 섞여 있으며 별도로 제거하지 않았습니다 — 원화 기준 수익률 그대로 사용합니다.

## 기간은 하나

**기간은 페이지 전체가 하나를 공유합니다** — 1일·1주·1개월·3개월·6개월·1년·3년·5년. 연결 기준 패널에서 바꾸든 주도주 패널에서 바꾸든 같은 값이고, 연결선의 상관계수와 주도주 순위가 함께 그 기간으로 다시 계산됩니다.

단 상관계수는 최소 한 달 치 관측이 있어야 성립하므로, 1일·1주를 고르면 네트워크는 **1개월 창으로 대체**하고 연결 기준 패널에 그 사실을 표시합니다. 없는 값을 있는 척하지 않습니다.

## 트레이딩 탭

종목 하나에 집중하는 화면입니다. 가운데는 봉차트(휠·축 드래그 확대, 추세선·수평선 그리기), 왼쪽은 즐겨찾기·보유·주도주 목록과 검색, 오른쪽은 종목 요약과 주문 티켓입니다. 네트워크의 종목 상세에서 **⤢ 봉차트**를 누르면 그 종목으로 바로 넘어옵니다.

보조지표는 MA(5·20·60·120), 볼린저밴드(20,2), 거래량 MA20, 그리고 보조창의 RSI(14) 또는 MACD(12,26,9)입니다. 모든 지표는 **전체 이력에서 계산한 뒤 보이는 구간만 잘라** 그립니다 — 확대할 때마다 다시 시작하는 120일 이동평균은 120일 이동평균이 아니기 때문입니다.

## 포트폴리오 · 모의 트레이딩 · 실거래

종목 상세의 **주문** 패널에서 매수·매도합니다. 모의와 실거래가 같은 장부에 기록되고, 실거래에는 "실" 표시가 붙습니다.

**모의와 실거래는 완전히 분리된 두 장부입니다** — 각자 보유 종목·거래 내역·실현손익을 따로 가집니다. 가상의 현금으로 산 종목과 실제로 산 종목을 한 줄에 더하는 것은 의미가 없기 때문입니다. 헤더의 `모의 / 실거래` 토글이 주문이 어느 장부로 들어갈지, 보유 목록이 어느 쪽을 보여줄지를 정합니다. 실거래 장부의 현금은 증권사 계좌에 있으므로 평가금액만 표시합니다.

**모의**는 이 브라우저 안에서만 도는 가상 거래입니다. 시장가는 최근 종가로, 지정가는 입력한 가격에 즉시 체결된 것으로 **가정**합니다 — 실제 지정가 주문은 체결되지 않을 수도 있으므로 시나리오 계산으로만 보세요. 현금이 모자라거나 보유 수량을 넘기면 주문이 막힙니다. 수수료와 국내 매도 거래세는 설정에서 바꿀 수 있고, 기본값(0.015% / 0.18%)은 예시일 뿐입니다.

평가금액·손익·비중은 **원화로 환산**해 한 줄에서 비교하고(환율은 시가총액 환산과 같은 값, 설정에서 변경 가능), 평균단가와 현재가는 그 종목이 거래되는 통화 그대로 둡니다. 암호화폐와 금 현물은 토스증권 주식 API 대상이 아니라 모의 거래만 가능합니다.

### 로그인 (구글 · 카카오 · 네이버)

**탭은 하나도 잠그지 않습니다.** 종목 네트워크·트레이딩·포트폴리오 모두 비회원이 열어서 둘러볼 수 있고, 차트·보조지표·주도주·종목 상세는 전부 그대로 동작합니다. 로그인을 요구하는 것은 탭이 아니라 **개인 데이터를 읽거나 쓰는 동작**뿐입니다.

| 비회원도 가능 | 로그인 필요 |
| --- | --- |
| 네트워크·마인드맵·비교, 트레이딩 차트와 보조지표, 주도주 목록, 종목 상세, 포트폴리오 화면 둘러보기 | 즐겨찾기(★)와 저장된 화면, 트레이딩의 즐겨찾기·보유 목록 탭, 주문(모의·실거래), 토스 보유 종목 가져오기, 장부 초기화 |

잠긴 것은 숨기지 않고 흐리게 두거나 🔒 를 붙여 둡니다 — 기능이 있다는 사실과 무엇이 필요한지가 보여야 하기 때문입니다.

세 provider 모두 **공개 클라이언트 ID만** 쓰고 비밀키는 쓰지 않습니다 — 실제 보호 장치는 각 콘솔의 도메인 허용 목록입니다. `data/auth.json` 에 발급받은 ID를 넣으면 활성화되고, 비워 두면 버튼이 "설정 필요"로 표시되며 비회원 모드로만 동작합니다.

| provider | 넣을 값 | 발급처 |
|---|---|---|
| Google | OAuth 2.0 웹 클라이언트 ID | console.cloud.google.com → 사용자 인증 정보 → 승인된 JavaScript 원본에 사이트 주소 |
| 카카오 | JavaScript 키 | developers.kakao.com → 앱 키 · 플랫폼(Web) · Redirect URI 등록 |
| 네이버 | 클라이언트 ID | developers.naver.com/apps → 네이버 아이디로 로그인 · 서비스/Callback URL 등록 |

**이 로그인이 무엇이고 무엇이 아닌지**는 분명히 해 둘 필요가 있습니다. 이 사이트는 서버가 없는 정적 페이지입니다. 로그인은 브라우저 안의 신원 확인이고, 한 기기에서 **계정별로 즐겨찾기와 장부를 분리**해 주는 역할을 합니다. 데이터는 여전히 그 브라우저의 저장소에 있으므로 **기기 간 동기화는 되지 않고**, 같은 기기 앞에 앉은 사람이 저장소를 직접 열어보는 것까지 막아 주지는 않습니다.

## 실거래 — 토스증권 Open API

토스증권 Open API는 OAuth 2.0 client credentials 방식이고, [토스 문서](https://developers.tossinvest.com/docs) 자체가 `client_secret`을 **서버에서만** 쓰라고 명시합니다. 이 사이트는 누구나 소스를 볼 수 있는 정적 페이지이므로 키를 넣을 수 없습니다. 그래서 주문은 **본인 PC에서 실행하는 브리지**를 거칩니다.

### 토스에서 가져오는 것

| 기능 | 경로 | 확장 | 파이썬 브리지 |
|---|---|---|---|
| 주문(매수·매도)·취소, 보유·계좌 조회 | REST | ✅ | ✅ |
| **1분봉** — 화면에 연 종목만, 최근 200봉 | REST `/candles` | ✅ | ✅ |
| **미체결 주문 추적** — 5초 폴링, 체결·취소·거부 알림 | REST `/orders` | ✅ | ✅ |
| **실시간 체결 시세** | 웹소켓 | ✅ | ❌ |

실시간이 확장 전용인 이유는 토스 웹소켓이 handshake 에 `Authorization` 헤더를 요구하는데 브라우저의 `WebSocket` 생성자로는 헤더를 붙일 수 없기 때문입니다. 확장은 `declarativeNetRequest` 로 그 요청에만 헤더를 덧붙여 연결합니다.

구독은 **선언형 full-replace** 라 배열 하나가 곧 구독 전체입니다. 분할 패널이 바뀔 때마다 지금 열린 종목 목록을 다시 보내면 나머지는 서버가 해제합니다 — 연결당 100건 한도에 우리는 최대 4건만 씁니다. 선언은 초당 5회 제한이 있어 350ms 로 묶어 보냅니다.

받은 체결가는 **마지막 봉의 종가·고저에만** 반영하고 거래량은 건드리지 않습니다. 스펙이 "프레임 합산으로 누적 거래량을 재구성할 수 없다"고 명시하기 때문입니다.

### 연결 방법 두 가지

브라우저는 CORS 때문에 `openapi.tossinvest.com` 을 직접 부를 수 없습니다(라이브에서 확인: `Access-Control-Allow-Origin` 헤더 없음). 중간에서 대신 불러 줄 것이 하나 필요하고, 두 가지 중 고를 수 있습니다.

| | 브라우저 확장 | 파이썬 브리지 |
|---|---|---|
| 설치 요건 | 없음 (Chrome·Edge·Whale) | Python 3 |
| 매번 할 일 | 없음 — 브라우저만 켜면 됨 | 터미널에서 실행 |
| 키 저장 위치 | 확장의 `chrome.storage.local` | `~/.money-connection/toss.json` |
| 페이지가 키를 읽을 수 있나 | 아니오 | 아니오 |

**확장** — 마법사에서 `.zip` 을 받아 압축을 풀고, `chrome://extensions` → 개발자 모드 → **압축해제된 확장 프로그램을 로드**. 로드되면 **설정 창이 저절로 열리므로** 세부정보를 뒤질 필요가 없습니다. 키를 넣고 저장하면 연결 확인까지 이어서 실행됩니다. 창을 놓쳤다면 툴바의 확장 아이콘(설정 전에는 `!` 배지가 붙습니다)을 누르면 다시 열립니다. 소스는 `build/extension/` 에 있습니다.

압축을 푼 폴더는 **지우거나 옮기지 마세요** — 크롬이 그 경로를 계속 참조합니다.

확장이 설치되어 있으면 대시보드가 자동으로 인식하고 브리지 주소는 필요 없어집니다.

### 가장 쉬운 길: 연동 마법사

**포트폴리오 → [연동하기]** (또는 계정 프로필 메뉴 → 토스증권 연동하기)를 누르면 발급부터 연결까지 한 단계씩 안내합니다. 키를 입력하면 `toss.json` 을 만들어 내려주므로 파일을 직접 쓸 필요가 없습니다.

**입력한 키는 이 사이트에 저장되지 않습니다.** 파일을 만드는 데만 쓰이고 창을 닫으면 메모리에서 사라지며, `localStorage` 에 기록되지 않습니다. 애초에 브라우저는 토스 API를 직접 부를 수 없습니다 — `openapi.tossinvest.com` 은 `Access-Control-Allow-Origin` 을 주지 않으므로 CORS 에서 차단됩니다. 그래서 브리지는 취향이 아니라 유일한 방법입니다.

아래는 마법사가 대신 해 주는 일을 손으로 하는 방법입니다.

### 브리지 주소란

브리지는 **내 PC에서 도는 작은 중계 프로그램**입니다. 키는 내 PC에만 두고, 브라우저는 이 프로그램에만 주문을 부탁합니다. "브리지 주소"는 그 프로그램의 주소이고, 실행하면 터미널에 그대로 표시됩니다 — 기본값은 `http://localhost:8787` 입니다.

### 순서

**1. 키 발급** — 토스증권 WTS(PC 웹) 로그인 → **설정 → Open API** → 신청 후 `client_id`, `client_secret` 을 받습니다.

**2. 키를 내 PC에 저장**

```bash
mkdir -p ~/.money-connection
cat > ~/.money-connection/toss.json <<'EOF'
{ "client_id": "발급받은 클라이언트 ID", "client_secret": "발급받은 시크릿" }
EOF
```

계좌가 여러 개면 `"account_seq": 1` 을 추가하세요. 없으면 첫 `BROKERAGE` 계좌를 씁니다.

**3. 브리지 실행** — 거래하는 동안 이 터미널은 켜 두어야 합니다.

```bash
python3 build/toss_bridge.py            # 127.0.0.1:8787, 표준 라이브러리만 사용
```

저장소를 받지 않았다면 연동 마법사 3단계의 **[toss_bridge.py 내려받기]** 로 이 파일만 받아 `python3 ~/Downloads/toss_bridge.py` 로 실행해도 됩니다. 스크립트는 페이지에 함께 실려 있어 별도 내려받기가 필요 없습니다.

**4. 연결 확인** — 대시보드 **포트폴리오 → 설정 → 토스증권 연결**의 *브리지 주소* 칸에 3번에서 표시된 주소를 넣고 **[연결 확인]**. 계좌번호가 뜨면 성공입니다. 실패하면 원인을 구분해서 알려 줍니다 — `Failed to fetch` 는 브리지가 꺼진 것, `invalid_client` 는 키가 틀린 것입니다.

**5. 보유 종목 가져오기** — 실제 계좌의 보유 수량·평균단가를 실거래 장부로 불러옵니다.

**6. 주문** — 상단 메뉴에서 **실거래**로 바꾸면 주문이 이 브리지를 거쳐 실제 계좌로 나갑니다.

브리지는

- `127.0.0.1`에만 바인딩하고, 허용된 origin에만 CORS를 엽니다
- 액세스 토큰을 캐시하고 만료 60초 전에 갱신합니다
- 계좌번호는 첫 `BROKERAGE` 계좌를 자동으로 잡습니다 (`account_seq`로 고정 가능)
- 주문·취소만 중계하며, 키는 로그에 남기지 않습니다

**이 포트를 외부에 노출하지 마세요** — 닿을 수 있는 모든 프로그램이 당신의 계좌로 주문을 낼 수 있습니다.

주문은 브라우저의 확인 창을 눌러야 전송되고, 접수되면 주문번호를 돌려줍니다. 체결 수량·가격의 최종 권위는 토스증권이므로, 장부를 맞추려면 **설정 → 보유 종목 가져오기**로 실제 보유 수량·평균단가를 덮어쓰세요(현금 잔고는 모의 값 그대로 남습니다).
